## What changed vs previous versions

This is the first dedicated feature doc for `Fault` at the v2.0 documentation baseline (library release line 2.0.x). Compared to the v1.3.x behavior that users already know from the README / changelog:

- Core `Fault` model, kinds, error codes, labels, audience messages, call stack, and builder remain the same conceptual design.
- Nil-safe `Fault` method behavior (from 1.3.6) is part of this baseline: calling methods on a nil `Fault` implementation does not panic.
- Authentication error codes `AUTHENTICATION_ERRCODE_EXPIRED` and `AUTHENTICATION_ERRCODE_INVALID` are included in the catalog.
- Illegal-state codes `ILLEGALSTATE_ERRCODE_SERIALIZATION_FAILED` and `ILLEGALSTATE_ERRCODE_DESERIALIZATION_FAILED` are included.
- Package identity constants `pkg.LIB_NAME` and `kt_errors.PACKAGE_NAME` exist for Fault sources and logging prefixes.
- Boundary conversion (`NewPublicFaultFromAnyError`) changed in 2.0 — see [PublicFaultConversion-v2.0.md](PublicFaultConversion-v2.0.md). This doc does not cover that API.

Within 2.0.x (release 2.0.4):

- `FaultBuilder.Build()` auth/authz non-retryable overrides now apply to the **returned** Fault (previously only an internal builder copy was updated). Documented behavior below was already the intended contract.
- Typed-nil `Fault` receivers: `Error()` / `String()` are nil-safe as well (`Error()` → `""`, `String()` → `"Fault{nil}"`).
- Added correctly spelled `ILLEGALSTATE_ERRCODE_EXPECTATION_FAILED`; misspelled `ILLEGALSTATE_ERRCODE_EXCPECTATION_FAILED` is deprecated (same value).
- `Add*` concurrency note; `WithSource` appends on repeat; `String()` limits nested cause depth.

## TLDR

- `Fault` is Keytiles’ unified, data-rich `error` type.
- Every Fault has a **kind**, optional **error codes**, **labels**, message **templates** (optionally per audience), optional **cause**, and optional **source / call stack**.
- A Fault is either **public** (safe to leave a boundary / show to users) or **non-public** (may leak internals).
- Create Faults with `NewFaultBuilder` / `NewPublicFaultBuilder`, then `Build()`.
- As a Fault bubbles up, prefer enriching it in place with `Add*` methods instead of wrapping into a brand-new error at every layer.
- For logging, prefer `String()` (or `kt_utils.VarPrinter`) over `Error()`.

## Concept

The goal is to avoid thin string-only errors and avoid heavy “map error at every layer” boilerplate. A Fault carries enough machine-readable and human-readable context that higher layers can usually:

- add a bit more context (`AddContextToMessage`, `AddErrorCodes`, `AddLabel(s)`, `AddCallerToCallStack`)
- or convert once at the public boundary (see PublicFaultConversion)
- or map once to HTTP/gRPC / JSON (see StatusCodeMapping / FaultSerialization)

`Fault` is semi-immutable: kind / public flag / core message are set at build time; enrichment via `Add*` is intentional mutation as the error travels upward.
`Add*` mutation is **not** safe for concurrent use on the same Fault instance — synchronize at the caller if needed.

## Fault kinds

`FaultKind` is a string alias. Kind is set at builder creation and cannot be changed later.

- `RuntimeFault` (`"runtime"`) — generic runtime failure
- `IllegalStateFault` (`"illegal_state"`) — unexpected state; pair with `ILLEGALSTATE_ERRCODE_*`
- `NotImplementedFault` (`"not_implemented"`) — not implemented
- `ValidationFault` (`"validation"`) — invalid input/data; pair with `VALIDATION_ERRCODE_*`
- `ConstraintViolationFault` (`"constraint_violation"`) — assumption / precondition failed; pair with `CONSTRAINTVIOLATION_ERRCODE_*`
- `ResourceNotFoundFault` (`"resource_not_found"`) — expected resource missing (also modelable via constraint violation + `CONSTRAINTVIOLATION_ERRCODE_DOES_NOT_EXIST`)
- `AuthenticationFault` (`"authentication"`) — auth data problem; pair with `AUTHENTICATION_ERRCODE_*`
- `AuthorizationFault` (`"authorization"`) — missing permission / authz failure; pair with `AUTHORIZATION_*`

Kind drives status-code mapping for public Faults — see [StatusCodeMapping-v2.0.md](StatusCodeMapping-v2.0.md).

## Public vs non-public

- `IsPublic() == true` — safe to leave the private boundary; messages should be clear and free of internal implementation details.
- `IsPublic() == false` — treated as unsafe. Do not serialize / return as-is to clients. Convert at the boundary with `NewPublicFaultFromAnyError`.
- Create public Faults with `NewPublicFaultBuilder(...)`.
- Create non-public Faults with `NewFaultBuilder(...)`.

## Retryable

- `IsRetryable()` is set via builder `WithIsRetryable(true/false)`.
- Some kinds are inherently not retryable: `NotImplementedFault`, `ValidationFault`, `ResourceNotFoundFault`. Calling `WithIsRetryable` on those has no effect.
- At `Build()`, some auth(z) combinations force non-retryable even if you asked for retryable:
  - `AuthenticationFault` with `AUTHENTICATION_ERRCODE_MISSING` or `AUTHENTICATION_ERRCODE_NOT_SUPPORTED`
  - `AuthorizationFault` with `AUTHORIZATION_NO_PERMISSION`

## Error codes

Inspection helpers:

- `GetErrorCodes()` — returns a **copy**
- `HasErrorCode(codes ...string)` — true if any listed code is present
- `AddErrorCodes(c ...string)` — append unique non-empty codes while bubbling up

## Messages and audiences

- Default developer-facing message is a **template**: Python-style placeholders like `"User {userId} not found"`.
- Placeholders resolve from labels via `GetMessage()` / `GetMessageForAudience(...)`.
- Unresolved templates: `GetMessageTemplate()` / `GetMessageTemplateForAudience(...)`.
- Audience messages live in a map. Built-in audience constant:
  - `MSGAUDIENCE_USER` (`"user"`) — especially important for public conversion (user message can become the public main message)
- Builder methods:
  - `WithMessageTemplate(msg)`
  - `WithMessageTemplateForAudience(forAudience, msg)`
  - `WithoutMessageTemplateForAudiences(...)`
  - `WithMessageTemplatesByAudience(map)` — merge
  - `WithExactMessageTemplatesByAudience(map)` — replace
- While bubbling up:
  - `AddContextToMessage(prefix)` — prepends to the default template (include separators/spaces yourself)
  - `AddContextToAudienceMessage(forAudience, prefix)` — prepends / creates audience message; prefix is trimmed on the right for new audiences

## Labels

- Labels are `map[string]any` key-value pairs attached to the Fault.
- Used for message variable resolution and extra structured context.
- Builder:
  - `WithLabel(key, value)` / `WithLabels(map)` (merge)
  - `WithoutLabels(keys...)`
  - `WithExactLabels(map)` (replace)
- Runtime:
  - `GetLabel(key)` / `GetLabels()` (copy)
  - `AddLabel` / `AddLabels` while bubbling up

## Cause, source, call stack

- Cause: any `error` via builder `WithCause` / `WithoutCause`; read with `GetCause()`.
- Source / call stack are cheap string hops (no runtime stack traces):
  - Builder `WithSource(parts...)` joins parts with `"."` and seeds the stack. Calling `WithSource` again **appends** another hop (does not replace).
  - `AddCallerToCallStack(parts...)` appends another hop as the error bubbles
  - `GetSource()` — origin (deepest)
  - `GetCallStack()` — copy, ordered from outer caller to source
- Convention: use `kt_errors.PACKAGE_NAME` (and method/component fragments) as source prefixes. Root lib name is `pkg.LIB_NAME` (`"keytiles.lib.errorhandling"`).

## Creating a Fault (builder)

```go
fault := kt_errors.NewPublicFaultBuilder(kt_errors.ValidationFault).
    WithMessageTemplate("Field {field} is invalid").
    WithMessageTemplateForAudience(kt_errors.MSGAUDIENCE_USER, "Please check {field}").
    WithLabel("field", "email").
    WithErrorCodes(kt_errors.VALIDATION_ERRCODE_INVALID_VALUE).
    WithSource(kt_errors.PACKAGE_NAME, "ValidateUser").
    Build()
```

Non-public:

```go
fault := kt_errors.NewFaultBuilder(kt_errors.IllegalStateFault).
    WithMessageTemplate("S3 GetObject failed for bucket {bucket}").
    WithLabel("bucket", bucketName).
    WithErrorCodes(kt_errors.ILLEGALSTATE_ERRCODE_DEPENDENCY_UNAVAILABLE).
    WithIsRetryable(true).
    WithCause(err).
    WithSource(kt_errors.PACKAGE_NAME, "LoadProfile").
    Build()
```

Builder API summary:

- Entry points: `NewFaultBuilder(kind)`, `NewPublicFaultBuilder(kind)`
- Finish: `Build() Fault`
- Content: `WithMessageTemplate*`, `WithErrorCodes` / `WithoutErrorCodes`, `WithLabel(s)` / `WithoutLabels` / `WithExactLabels`, `WithCause` / `WithoutCause`, `WithSource`, `WithIsRetryable`

## Enriching while bubbling up

Prefer this over remapping to a new error type at every layer:

```go
if ok, fault := kt_errors.IsFault(err); ok {
    fault.AddCallerToCallStack(kt_errors.PACKAGE_NAME, "HandleRequest")
    fault.AddContextToMessage("handle request: ")
    fault.AddLabel("requestId", requestId)
    return fault
}
```

## Type check helper

- `IsFault(err) (bool, Fault)` — true + Fault if `err` implements `Fault`; nil error is not a Fault.

## Logging and string forms

- `Error()` — compact `error` interface form. For non-public Faults it omits labels to reduce leak risk. For public Faults it includes labels. Nil receiver → `""`.
- `String()` — full diagnostic form (kind, template, retryable, public, codes, call stack, cause, audience messages, labels). Prefer this for logs. Nil receiver → `"Fault{nil}"`. Nested Fault causes are printed recursively up to a fixed depth (then `{...}`) to avoid runaway stacks.
- Tip from the interface docs: use `kt_utils.VarPrinter{TheVar: fault}` so `String()` is used instead of Go’s default `Error()` path for `error` values.

Convenience wrappers on `Fault`:

## Nil safety

Methods on the default Fault implementation are nil-safe (including `Error()` / `String()`): they return empty/zero values instead of panicking when the receiver is nil.
